# C04: Syntax/detection fallback

**Scope:** `ide-syntax`. The component must be implemented, not just compile. See `ARCHITECTURE.md` and `tests/TEST_MATRIX.md`.

## Public interface concepts

LanguageProfile, GrammarRegistry, TokenSpan, SyntaxCapability. Concrete Rust API design is owned by the architecture agent and must remain versioned and acyclic. Use explicit immutable IDs, typed error surfaces, bounded async notifications and capability negotiation where appropriate.

## Acceptance and fixtures

file type detection/shebang, parser fallback, unknown extension, injection tests. Record command, target runtime, exit status, negative cases and evidence file hashes. Include regression cases, not just success path. Benchmark where on critical path.

## Threat/failure scenarios

Parser crash from untrusted grammar, blocking large file. These are mandatory negative tests. Fault injection must never corrupt the authoritative document, change host security settings, or leak credentials.

## Ownership and dependency

The relevant graph task in `engineering/graph/seed.json` owns this contract. When an interface changes, mark dependent tests, proofs and implementations dirty. Accepted laws cannot be weakened. Unit tests do not replace actual interactive TUI verification.
